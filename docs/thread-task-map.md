# Thread Task Map

一任务一张图。它是当前任务的本地计划，不是第二份聊天记录。核心任务与分支在首次显示时保存；后续对话和摘要刷新不会重建计划。

## 使用

右栏默认显示「任务图」，也可切换到上下文、Skills 或资产。

- 拖动节点调整位置，拖空白平移，滚轮或 `+` / `−` 缩放；「适应」显示全图，「整理」恢复初始坐标。
- 双击或按 `F2` 编辑标题和摘要；方向键移动节点，`Shift` 加大步长，`Home` 适应画布。
- 「添加」把新节点连接到选中节点；状态菜单可设置未知、待处理、进行中、已完成、阻塞或已取消。核心状态由摘要提供。
- 「删除」仅删除选中的自建节点及其自建子节点，需要确认；不会删除源文件或 Codex 消息。
- 「导出」保存 JSON，包含图文档、当前显示节点及视口，不包含完整对话。
- 「展开画布」将对话与任务图区分为 1/3 和 2/3，暂时收起左侧导航；收起画布恢复布局。

节点详情显示状态、来源和更新时间；文字大纲提供相同的节点层次。编辑只写本地计划，不发送消息。

## 主动同步

当前助手通过已有摘要维护流程更新 `task-context.taskMap`。增强器刷新摘要时，按稳定的节点 `id` 同步已记录的状态；「同步」可再次应用当前摘要。不调用额外模型，不从「会话空闲」推断工作完成。

同步只接受有效状态、来源和 ISO 时间；忽略早于本地图记录的进度。核心文字、分支名称、摘要与子节点结构保持不变。手动状态优先于摘要状态；仅编辑文字不会锁死后续状态更新。没有记录时显示「未知」，不猜完成比例。

在现有任务摘要中添加可选的 `taskMap`：

```json
{
  "coreTask": {
    "text": "完成示例项目",
    "state": "in-progress",
    "source": "user-confirmed",
    "updatedAt": "2026-09-14T00:00:00Z"
  },
  "branches": [
    {
      "id": "implementation",
      "label": "实现",
      "text": "交付可运行的功能",
      "state": "pending",
      "source": "task-summary",
      "updatedAt": "2026-09-14T00:00:00Z",
      "children": [
        {
          "id": "checks",
          "text": "完成针对性检查",
          "state": "pending",
          "source": "task-summary",
          "updatedAt": "2026-09-14T00:00:00Z"
        }
      ]
    }
  ]
}
```

摘要仍需现有的 `threadId`、`updatedAt`、`goal`、`progress`、`nextStep`、`agreements` 字段。各主分支和同一分支下的子节点使用唯一、稳定的 ID。只写精简计划、事实状态和稳定引用，不复制提示词或完整消息。

## 存储与边界

图保存在 Codex renderer 的 localStorage：`codex-workspace-enhancer:mindmap-layouts-v1`。保留最近更新的 40 个任务；每张图最多显示 6 个主分支、每分支 5 个叶节点和 20 个自建节点。文字有长度上限。清理本地应用数据会移除这些图，需要长期保存时使用 JSON 导出；当前没有导入入口。

任务切换、面板关闭或原生右侧面板打开时停用旧图，迟到的旧任务快照不会覆盖当前图。任务 ID 是隔离键；同目录的不同任务不共用计划。图中的来源和时间来自摘要或明确的本地编辑，不表示用户已验收。

界面依赖 Codex 的内部布局。自动化测试覆盖模型、动作回调、保存、同步及任务隔离；不替代当前桌面版本的视觉与交互验收。
